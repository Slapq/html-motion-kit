# 实战经验与坑

几支宣传片/教程踩出来的清单。每条都是**真实发生过的失败**。按规则强度分三级：

| 级别 | 含义 | 在哪 |
|---|---|---|
| **硬规则** | 违反 = 画面坏掉或 audit 阻塞（退出码 1），导出前必须满足 | 第 1、2 节 |
| **强建议** | 违反不会报错，但用户会直接说"不好看"；audit 只给「提示」或不管 | 第 3、4 节 |
| **参考** | 参数语义、流程细节，查到再看 | 第 5、6 节 |

新项目开工前扫一遍第 1、2 节；audit 报了什么就查第 7 节的对照表。

---

## 0. 最重要的一条：先量，再看

**症状**：靠 `motion_still` 一张一张抽帧看画面，一轮 5 分钟，看完还是漏。同一个"第二章整章空白"的 bug **连续犯了两遍**，因为每次只抽 1~2 个时间点，恰好都没抽中。

```bash
node tools/audit.mjs projects/<name> --step 0.1            # 全片
node tools/audit.mjs projects/<name> --step 0.1 --to 12    # 只扫前 2~3 段
```

一次浏览器扫完全片，用数字报结果，20 秒出结论，**不靠肉眼**。输出分两级：

- **问题（阻塞）**：裁切、出画、压叠、空帧/偏空、静止、对比度、节奏违规、镜头超速、页面报错。导出前必须 `0 条阻塞问题`。
- **提示（不阻塞）**：交接无延续、dense 段文字太少、颜色 >6 种、字号 >7 种。默认打印（`--no-hints` 关闭），能改就改。

**写完前 2~3 段就先审一次**，别等全片写完再返工。看图只在两种情况下用：audit 报了点位，或者要判断"好不好看"（审美，工具管不了）。

## 1. 硬规则：API 事实（别猜，读源码）

猜 API 是最高频的失败来源。以下都是**亲自踩过**的：

| 你以为 | 事实 | 后果 / 出处 |
|---|---|---|
| `inOutSine` 能用 | 早期**没有 Sine**，未知名字静默回退 | 已修：未知缓动名**直接抛错**并列出可用名（`engine/ease.js` 的 `resolveEase`）。textIn 预设、转场类型、粒子模式、rhythm 同样会报 |
| `tl.to([a, b], …)` 能同时动两个 | 传数组是**静默无效**：`isEl` 对数组返回 false，什么都不发生 | 多个元素用 `fx.staggerIn` 或逐个 `tl.to`（marathon 踩过） |
| `keys: [[t, v, ease]]` 的 ease 管"从这一键出发" | 管的是**到达这一键**的那一段 | `engine/graph.js:86`。搞反会"该停时在动、该动时停住" |
| `__video.info` | 没有这个字段 | 实际是 `width/height/fps/duration/chapters/props/seek/audioWav/hasAudio/inspect/timeline`。`seek(t)` 返回 Promise，resolve 时已完成一帧 |
| `tl.add((lt, t) => …)` 的第二参是场景时间 | 第二参是**全局时间**，第一参才是场景内的 | `engine/player.js`；每帧回调按注册顺序执行 |
| 音效只在本场景响 | 音频 cue 是**全局**的：`this._o + this._t(at)` | 第一幕排一条 `pad dur: 24` 能铺满全片 |
| `--out` 相对项目目录 | CLI 的 `--out` **相对 CWD** | DSH 的 `motion_still` 才约束在项目目录内 |
| `ShaderLayer` / `Space3D` 自动垫底 | canvas 是 `appendChild`，默认 `z-index: 0` | 会**盖在文字上面**，正文要显式 `z-index` |
| `base.css` 够用 | `.stage` 是深色 `--bg:#0b0f1a`，`.captions` 黑底白字 | 浅色主题必须覆盖这两个（或用 `look: 'light'`） |
| `fx.textIn` 只动文字 | 它用 `splitText` **重写 innerHTML** | `<h2>标题<small>副</small></h2>` 的嵌套会被吞，副标题放独立元素 |
| `counter` / `typewriter` 能写进任意元素 | 用 `textContent` 写入，子元素会被清掉 | 目标必须是叶子节点，如 `<b class="n1">0</b>` |
| 同一段里两个 `data-carry="x"` 没关系 | 直接抛错 `duplicate data-carry` | 名字在一段内唯一，跨相邻段同名才配对 |
| 光标每个场景各建一个 | 全片**只有一个**光标（`ctx.cursor`），路径按时间排序拼接 | 旧的 `fx.cursor` 是场景内独立光标，不会跨交界 |

**规则**：用任何没亲手用过的 API 前，`grep` 一下引擎源码确认签名；报错信息（`unknown ref` / `unknown envelope` / 未知 blend）会直接抛，**看报错改**。

## 2. 硬规则：画面与版面

每一条违反都会直接让画面坏掉，或者被 audit 判成阻塞。

### 2.1 不许有一帧静止："不像 PPT"靠连续性

**症状**：用户原话"画面效果还是太简单了，根本无法和PPT相区分"。四幕切成四刀，每幕"入场 → 静止 3 秒 → 切走"，这就是 PPT。

**规则**：三样东西**从头到尾不许停**。audit 报「静止」= 连续 ≥1.5s 帧差 <0.4。

1. **镜头**：连续模式下章节横排成长画布，镜头一路平移，到位后留 ~10px/s 漂移（引擎自动做）。
2. **背景**：`background: 'network'` 之类每帧重算的 canvas。
3. **进度轴**：`progress: true`，底部刻度按真实时间匀速走。

**坑**：画面大半被不透明卡片/大图盖住时，背景和 10px/s 漂移露出的面积太小，照样会被判「静止」；光标、细进度条、小计数器这类小面积运动也不够。这时要让**大块内容**动：`fx.highlight` 框出下一处重点、给静态大图加 `fx.kenBurns` 慢推、或者缩短 hold（motion-kit-promo / motion-kit-take 都是这样修的）。

### 2.2 镜头 ≤ 80px/帧：要算缓动导数峰值

**症状**：审计报"最大单步位移 404px/0.1s"，换算 30fps 是 135px/帧，画面会顿。

**根因**：峰值速度 = 平均速度 × 缓动峰值斜率。`inOutQuad` 峰值是 2×，`inOutCubic` 是 **3×**（我一开始当成 1.5×，算错过一版）。

**规则**：`距离 / 时长 × 斜率 / 30 ≤ 80`。引擎的相机和 carry 都已按这条自动限速，自己写 `tl.to` 移动大元素时要自己算。

### 2.3 不许空帧：转场/交界处内容要交叉

- 场景模式：本场景内容在最后 `T` 秒淡出（`[dur-T, dur]`，不要提前），下一场景在转场一开始就入场。
- 连续模式：章节内容在 `ctx.arrive`（镜头到位）**之前**就开始入场。
- 第二章整章空白的两个真实根因：面板没给 `left`；内容到站才开始入场。

### 2.4 节奏标签

- 场景/章节可标 `rhythm: 'anchor' | 'dense' | 'breathing'`，写错直接阻塞。
- `breathing` 合计 **≤ 全片 30%**，且**不能连续两段**，违反是阻塞问题。breathing 段放宽「偏空」「静止」，所以不能靠它糊弄审计。

### 2.5 布局

| 坑 | 根因 | 规则 |
|---|---|---|
| 整章内容跑到画面外 | `position: absolute` 只给了 `top`/`width`，没给 `left`，落到静态位置 | 绝对定位**成对给偏移** |
| 图表柱子和窗口标题栏一起变色 | 单文件只有一份全局 CSS，`.bar` 撞车 | 类名按章节命名空间（`.cbar` / `.code-card > .bar`） |
| 数字行被判「裁切」 | 中文字体下 `line-height: 1` 墨迹超出盒子 | 用 `normal` 或 `1.2` |
| 卡片高度打字时跳动 | `pre` 内容变长撑高容器 | 给 `min-height` 固定住 |
| 浅色底上文字对比度不够 | 灰色正文 / 主色小字 | 正文 ≥4.5:1、大字 ≥3:1；加深颜色或加底 |

## 3. 强建议：视觉（用户会直接说"不好看"）

### 3.1 别把节拍接到画面上

**症状**：用户原话"你为什么那么喜欢用呼吸特效呢？这个特效会让画面一闪一闪，并不好看"。

**根因**：一条 `{ type: 'pulse', bpm: 96 }` 通道 `link` 到整屏亮度和几处 `scale`，96bpm 就是每秒闪 1.6 次。

**规则**：**节拍属于音频，不属于画面**。要"跟着音乐"就用离散事件（某个时刻的一次 `thump` 加一次位移）。整屏亮度变化几乎永远是错的。

### 3.2 内容层不抖、不漂

**症状**：用户原话"以及奇怪的震动，这个也不要"。根因是标题上的 `fx.shake`，以及卡片上带 `rot` 的 `fx.float`。

**规则**：内容层只做**有目的的入场**（位移 + 淡入）。要"活着"的感觉，交给背景层和镜头。

### 3.3 大字号标题不用逐字 blur/scale

**症状**：用户原话"开场的字母糊在一起了"。根因是 `blur` 预设：15 个字同时放大加模糊，叠成一团。

**规则**：显示级字号（>64px）用整行 `fx.textIn(…, { preset: 'line' })` 或 `tl.from(el, { opacity: 0, y: 28 }, { dur: 0.95, ease: 'outCubic' })`。逐字预设留给小字。

### 3.4 一镜到底的三条方法

1. **交接处才是要设计的东西。** 如果没有任何东西活到下一段，那就是翻页。每个交界至少延续一样东西：两边放同名 `data-carry`（元素在屏幕空间飞过去），或者让 `ctx.cursor` 带着观众走过去。audit 用「交接」提示检查这一点。**先设计交接，再设计内容。**
2. **静止是手段。** 关键动作（点击、数字落定、结论出现）之后，内容层停 0.4–1s。背景和镜头照常漂移，所以不会被判「静止」。
3. **因果要可见。** 光标点一下，面板展开；敲进命令，结果出现。光标是贯穿全片的主线（`--mode tutorial` 模板就是这个骨架）。

### 3.5 配色与字号收拢

- "科技感" ≠ 深色霓虹。默认走**中性**（白底 + 单一主色），或者**先要参考**。按一个词自己定了深色霓虹，整支片子被推翻重做。
- 文字颜色 ≤6 种、字号 ≤7 级（audit 提示），收拢到 `:root` 变量和 `.h1/.h2/.lede/.sub`。
- `fx.particles` 的 `bokeh` 在浅色底上像污渍，`stars` 会闪烁。要氛围就用极慢漂移的大色斑。

## 4. 强建议：交接与光标的写法

- `data-carry` 两端内容可以不同（例如大标题 → 角落小标签）：几何插值，中间 30% 交叉淡化。两端差太多时看起来像"变形"，最好是同一句话或同一图标。
- carry 飞行时长 = max(转场/镜头时长, 限速时长)。飞行期间目标原件隐藏，所以**不要给目标元素再加入场动画**（会被遮住，白做）。
- 光标点击后用 `then: (ct) => …` 挂结果出现，保证"点了才变"。`press: true` 只对元素目标有效。
- 光标不需要时 `{ hide: t }` 让它退场，下一次移动会自动淡入。

## 5. 参考：参数语义

- **`falloff` 的 `rest`**：权重为 0 处的克隆仍保留 `rest` 比例的效果。给 `opacity` 配 `rest: 0.05`，大部分克隆近乎隐形。
- **`distribution.center` 是父容器局部坐标**：面板宽 732 就写 `center: [366, …]`。
- **`pulse` / `step` / `env` 是给音频和数据通道用的**，`link` 到视觉属性就会变成闪烁（3.1）。
- **`counter` 的 `ease` 默认是 `outExpo`**：想要匀速推进，显式写 `ease: 'linear'` 或 `inOutCubic`。
- **`graph` 的 `keys` 有 `loop`**：做"每 4 秒重复"用 `loop: 4`。
- **审计量墨迹不量盒子**：`left:0; right:0` 的居中标题盒子本来就满宽，出画判断用 `Range.getBoundingClientRect()`。

## 6. 参考：流程

1. `motion_new` → 写前 2~3 段 → **audit** → 写完 → **audit** → 抽 1~2 帧看审美 → 导出。
2. 报错看 `[page error]`，未知 ref / blend / envelope / rhythm 都会明确抛出。
3. `tl.inspect()` 是**构建期**查询，放进每帧回调会拖慢渲染。
4. 导出用 `--workers 4`；24 秒 720 帧约 12 秒渲完。
5. 出现 `The browser is already running for …puppeteer_dev_chrome_profile-*`：删掉 `$env:TEMP` 下残留的空 profile 目录再重试。
6. 定稿后 `projects/<name>/` 只留 `index.html`、`out.mp4`、`poster.png`（和 `assets/`），临时 PNG 清掉。
7. `--step 0.2` 偶尔报「偏空」、`--step 0.1` 没有：这是采样步长的边界效应，以 0.1 为准。

## 7. audit 报了什么 → 怎么改

| audit 条目 | 级别 | 通常根因 | 推荐改法 |
|---|---|---|---|
| 裁切 | 阻塞 | 固定高度容器 / `line-height: 1` / `overflow: hidden` | 去掉固定高度，行高用 `normal`/`1.2`，或缩字号 |
| 出画 | 阻塞 | 绝对定位只给了一边偏移；distribution 用了错误坐标系 | 成对给偏移（2.5）；检查 `center` 是否是局部坐标 |
| 压叠 | 阻塞 | 两段内容同时在场（转场重叠），或 flex/grid 空间不够 | 错开入场/退场时间；加 `gap` 或减少条目 |
| 空帧 | 阻塞 | 上一段提前淡出、下一段到站才入场；面板没给 `left` | 按 2.3 让内容交叉；连续模式在 `ctx.arrive` 前入场 |
| 偏空 | 阻塞 | 可见文字 <3 块持续 ≥0.8s | 提前下一批内容；或确是留白就标 `rhythm: 'breathing'`（受 30% 限制） |
| 静止 | 阻塞 | 没有背景层 / 场景模式关了 drift / 长时间 hold | 开 `background`；让内容推进（打字、计数、光标移到下一处）；缩短 hold |
| 对比度 | 阻塞 | 浅灰字、主色小字、半透明文字 | 加深文字色（正文 ≥4.5:1，大字 ≥3:1）或给背景加底 |
| 节奏 | 阻塞 | rhythm 写错 / breathing 超 30% / 连续两段 breathing | 改成可用值；把部分 breathing 改成 anchor/dense 或缩短 |
| 镜头 | 阻塞 | 手写大位移动画太快；缓动峰值斜率没算 | 拉长时长或换 `inOutQuad`（2.2） |
| `[page error]` | 阻塞 | 未知缓动/预设/转场/rhythm、重复 `data-carry`、JS 错误 | 看报错里的 available 列表改 |
| 交接 | 提示 | 交界两边没有同名 `data-carry`，光标也没在 ±0.4s 内出现 | 给两边同一元素加 `data-carry="名字"`，或让 `ctx.cursor` 跨过去（3.4） |
| 节奏（dense） | 提示 | 标了 dense，平均文字块 <4 | 补内容，或改标 anchor |
| 色号 | 提示 | 文字颜色 >6 种 | 收拢到 `--fg/--muted/--accent` |
| 字号 | 提示 | 字号 >7 级 | 收拢到 `.h1/.h2/.lede/.sub` 几级 |

## 8. 导出前检查表

硬规则（audit 会拦）：

- [ ] audit `--step 0.1`：**0 条阻塞问题**、**0 条页面错误**
- [ ] 全部缓动名 / 预设 / 转场 / rhythm 在可用列表里
- [ ] breathing ≤ 30%，没有连续两段

强建议（audit 只提示或不管，要自己看）：

- [ ] 每个交界至少**一样东西延续**（`data-carry` 或光标）
- [ ] 关键动作后内容层停 **0.4–1s**；每个画面变化都有**看得见的起因**
- [ ] 画面里**没有** pulse 驱动的亮度/缩放，内容层**没有** shake/float/rotate
- [ ] 大字号标题整行入场，没有逐字 blur/scale
- [ ] 浅色主题覆盖了 `.stage` 背景与 `.captions`；CSS 类名没有跨章节重名
- [ ] 导出后 `ffprobe` 有 video+audio 流、时长正确；`volumedetect` 峰值 **≥ −9dB 且 ≤ −3dB**
